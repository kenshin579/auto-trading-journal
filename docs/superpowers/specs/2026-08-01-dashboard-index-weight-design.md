# 대시보드 "지수 vs 나머지 투자" 섹션 설계

- 작성일: 2026-08-01
- 상태: 설계 확정 (구현 전)

## 배경 / 목적

투자 앱에서 내 수익률을 지수와 비교하면 지수 쪽이 더 낫다. 그래서 **앞으로 들어갈 돈을
지수 쪽으로 더 배분할지 판단**하기 위해, 지금 내 돈이 지수와 그 외에 각각 얼마나 들어가
있는지 대시보드에서 바로 보고 싶다.

여기서 "지수"는 시장 전체를 통째로 사는 패시브 노출을 말한다 — S&P500, 나스닥,
코스피·코스닥이 중심이고, 다른 국가·전세계 시장대표 지수도 성격이 같으므로 포함한다.
테마·섹터 ETF, 배당·전략 ETF, 채권·금, 개별종목은 모두 "나머지"다.

회고용 지표가 아니라 **다음 매수 결정의 근거**로 쓰므로, 숫자가 부풀려지거나 왜곡되면
판단이 반대로 갈 수 있다. 정확도가 단순함보다 우선한다.

## 현재 상태

- 국내: `internal/bizcat` 이 ETF 에 `섹터="ETF"`, `산업=카테고리`(고정 25종 taxonomy)를
  이미 넣고 있다. 캐시 117종목 중 89개가 ETF.
- 해외: `internal/fmpcat` 이 FMP `Company.Profile` 의 영문 섹터/산업을 넣는다. ETF 는
  공란이 아니라 `Financial Services / Asset Management*` 로 채워진다(CLAUDE.md 의
  "해외 ETF 는 공란" 기술은 실제 캐시와 어긋난다 — 이 작업에서 바로잡는다).
- 대시보드(`internal/summary`)의 모든 비중 지표는 **누적 매수금액** 기준이다.

문제:
1. `Asset Management` 문자열만으로 해외 ETF 를 가르면 MAIN·HTGC·BXSL(BDC), BN(브룩필드)
   같은 개별종목이 ETF 로 오분류된다.
2. 기존 taxonomy 는 `미국주식` 한 칸이라 S&P500 과 나스닥을 구분할 수 없다.
3. 누적 매수금액만으로는 이미 전량 매도한 종목이 계속 비중에 잡힌다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 지수 범위 | 시장대표 지수 전반(특정 국가/전세계 시장 전체 노출). 그 안에서 S&P500/나스닥/한국/기타지역으로 세분 표시 |
| 금액 기준 | 누적 매수금액과 보유 원금 **두 열 병기** |
| 분류가 사는 곳 | 데이터 소스(`fmpcat`/`etfclass`)를 정비하고 대시보드는 단순 매핑만 (거래 시트 스키마 변경 없음) |
| 표시 위치 | "투자 지표" 섹션 바로 다음, "매매 인사이트" 앞 |
| 차트 | 보유원금 기준 파이 1개 |

거래 시트에 "자산구분" 컬럼을 추가하는 안은 기각했다. 섹터/산업에서 파생되는 값의 중복
저장인 데다, 컬럼이 늘면 기존 시트가 헤더 불일치로 스킵되어(CLAUDE.md 명시 동작) 시트를
지우고 재생성해야 한다.

## 시트 출력 형태

"투자 지표" 섹션 다음, `A:E` 5열. 금액은 모두 원화.

```
[지수 vs 나머지 투자]
구분                     누적매수금액   비중    보유원금   비중
▸ 지수                   ₩12,000,000   38%    ₩8,500,000  45%
    S&P500                ₩5,000,000   16%    ₩4,000,000  21%
    나스닥                ₩4,000,000   13%    ₩3,000,000  16%
    한국(코스피·코스닥)    ₩2,000,000    6%    ₩1,000,000   5%
    기타 지역·전세계        ₩1,000,000    3%      ₩500,000   3%
▸ 나머지                 ₩19,600,000   62%   ₩10,400,000  55%
    개별종목             ₩12,000,000   38%    ₩7,000,000  37%
    테마·섹터 ETF         ₩5,000,000   16%    ₩2,400,000  13%
    배당·전략 ETF         ₩1,600,000    5%      ₩600,000   3%
    채권·금·현금성 ETF      ₩1,000,000    3%      ₩400,000   2%
```

- "나머지"도 4줄로 쪼갠다. 지수 비중을 늘리려면 어디서 빼올지 봐야 하는데, 개별종목
  38% 인지 테마 ETF 38% 인지에 따라 결정이 달라진다.
- 금액이 0 인 줄은 그대로 표시한다(구조가 매번 같아야 눈이 익는다). 단 `미분류` 줄만
  금액이 0 이면 감춘다.

## 컴포넌트 설계

### 신규 `internal/etfclass`

ETF 종목명 → 고정 taxonomy 안의 카테고리 하나. 현재 `internal/bizcat/etfclass.go` 를
그대로 옮기고 `Classify` 를 export 한다.

- 책임: 종목명 문자열 하나를 받아 카테고리 하나를 돌려준다. 그 외 아무것도 모른다.
- 의존: `go-openai` 뿐.
- 분리 이유: 국내(`bizcat`)와 해외(`fmpcat`) 가 **둘 다** 쓴다. 한쪽 패키지에 남겨두면
  다른 쪽이 그 패키지 전체(KIS 클라이언트 등)에 의존하게 된다.

taxonomy 변경 — 기존 25개 중 `미국주식` 한 칸만 셋으로 쪼갠다(총 27개).

```
변경 전: 한국주식, 미국주식, 중국주식, 일본주식, 인도주식, 베트남주식, 글로벌주식
변경 후: 한국주식, S&P500, 나스닥, 미국주식(기타), 중국주식, 일본주식, 인도주식,
        베트남주식, 글로벌주식
```

나머지 카테고리(섹터/테마 12종, 자산군 5종, 기타테마)는 그대로.

프롬프트에 명시 규칙 3개를 추가한다. 이걸 빼면 지수 비중이 실제보다 부풀려진다.

1. **커버드콜은 지수가 아니다.** JEPI(S&P500 기반)·JEPQ(나스닥 기반)는 이름에 지수가
   들어가지만 옵션 전략이라 지수 수익률을 따라가지 않는다 → `배당`
2. **레버리지·인버스는 지수가 아니다.** TQQQ, 곱버스류 → `기타테마`
3. **팩터·스타일도 지수가 아니다.** SCHG(성장주)·SCHD(배당성장)처럼 지수에서 골라 담은 것
   → `배당` 또는 `기타테마`

### `internal/bizcat`

- ETF 분류 호출을 `etfclass` 로 교체(로직 이동, 동작 동일).
- taxonomy 가 바뀌므로 캐시 버전 `v3 → v4`. 기존 ETF 항목은 `needsRefresh` 로 자동 재분류.

### `internal/fmpcat`

이 작업의 핵심 변경.

- 캐시 `entry` 에 `isETF bool` 과 버전 필드 `v` 추가. 현재 무버전 → `v2` 로 시작하고,
  버전이 없는 기존 105건은 1회 재조회.
- `fetch` 가 `Profile` 에서 `Sector`/`Industry`/`IsEtf`/`IsFund`/`CompanyName` 을 함께
  읽는다. **이미 받고 있는 응답의 필드라 API 호출 횟수는 그대로 1회.**
- `IsEtf || IsFund` 이면 국내와 동일하게 `섹터="ETF"`, `산업=etfclass.Classify(CompanyName)`.
  CompanyName 이 비면 티커로 분류.
- 일반 종목은 지금처럼 FMP 영문 섹터/산업 그대로.

부수 효과(의도한 것): 거래 시트에서 SCHD 가 `Financial Services` 가 아니라 `ETF / 배당`
으로 보이고, "나라별 섹터 비중" 섹션의 해외 부분도 국내와 같은 체계로 정확해진다.

### 신규 `internal/summary/index_weight.go`

- `bucketOf(sector, industry string) (group, bucket string)` — 순수 함수. 시트 없이 테스트된다.
  `group` 은 `지수` / `나머지` / `미분류` 셋 중 하나다. `미분류` 는 두 그룹 어디에도 속하지
  않는 독립 그룹이며, 소계 줄 없이 한 줄로 표시된다.
- `aggregateIndexWeight(trades []model.Trade) indexWeightTable` — 종목 단위 집계.
- `writeIndexWeight(ctx, trades, startRow) (int, error)` — `A:E` 작성 + 숫자/퍼센트 포맷 +
  헤더 색상 + 차트 헬퍼 데이터.
- `summary.go` 의 `GenerateAll` 에 `writeInvestmentMetrics` 다음으로 삽입하고 차트 1개 추가.

### 변경 없는 곳

- `internal/writer`: `BackfillSectors` 가 이미 국내/해외 시트의 섹터/산업 열을 조건 없이
  덮어쓴다. 캐시만 새로 채워지면 `make backfill-sectors` 한 번으로 기존 행이 갱신된다.
- `cmd/atj`: `fmpcat` 생성자 시그니처가 바뀌면 그 한 줄만.
- 거래 시트 스키마(국내 12열 / 해외 17열) 그대로.

## 분류 매핑

| 표시 줄 | 들어오는 것 |
|---|---|
| **▸ 지수** | 아래 4줄의 합 |
| S&P500 | `S&P500` |
| 나스닥 | `나스닥` |
| 한국(코스피·코스닥) | `한국주식` |
| 기타 지역·전세계 | `미국주식(기타)`, `중국주식`, `일본주식`, `인도주식`, `베트남주식`, `글로벌주식` |
| **▸ 나머지** | 아래 4줄의 합 |
| 개별종목 | 섹터 ≠ `ETF` 인 모든 거래 |
| 테마·섹터 ETF | `반도체`, `2차전지`, `바이오·헬스케어`, `AI·로봇`, `신재생에너지`, `원자력`, `방위·우주항공`, `자동차`, `금융`, `건설`, `필수소비재`, `IT·인터넷`, `리츠·부동산`, `기타테마` |
| 배당·전략 ETF | `배당` |
| 채권·금·현금성 ETF | `채권`, `원자재`, `통화·단기금리` |
| 미분류 | 섹터가 비었거나, 섹터가 `ETF` 인데 산업이 taxonomy 밖 |

`미분류` 를 "개별종목" 에 합치지 않는다. 합치면 지수 비중이 실제보다 낮게 보이고,
숫자가 안 맞을 때 어디가 빠졌는지 알 수 없다.

## 계산

종목 단위로 묶는다. 키는 `(종목코드, 종목명, 계좌, 통화)` — 기존 `aggregateStock` 과 동일.

```
평균매수단가 = 총매수금액(원) / 총매수수량
잔여수량   = max(0, 총매수수량 - 총매도수량)
보유원금   = 잔여수량 × 평균매수단가
```

- 매도가 매수를 넘는 경우(과거 이관분 등)는 음수 대신 0.
- 버킷은 종목 단위로 한 번 정한다. 같은 종목의 거래는 모두 같은 칸에 들어간다.
  섹터/산업은 그 종목 거래 중 처음 만나는 비어 있지 않은 값을 쓴다.
- 비중 분모: 누적 열은 전체 누적 매수금액, 보유 열은 전체 보유 원금. 분모에는 `미분류` 도
  포함하므로 `지수 + 나머지 + 미분류` 가 각 열에서 100% 가 된다.

## 데이터 흐름

```
CSV → parse → 섹터 보강 ─┬─ 국내: bizcat  → ETF면 ("ETF", 카테고리)   [기존]
                        └─ 해외: fmpcat  → ETF면 ("ETF", 카테고리)   [변경]
                              ↓
                        거래 시트 기록                              [기존]
                              ↓
                    ReadAllTrades → 대시보드
                              ↓
              aggregateIndexWeight → 지수/나머지 표 + 파이 차트     [신규]
```

새로 생기는 외부 호출 경로는 없다.

## 차트

보유원금 기준 파이 1개(지수 / 나머지 / 미분류). 소스 데이터는 **`Y:Z` 열**에 쓴다.

- `N:O` 는 계좌별 투자비중 파이, `W:X` 는 나라별 섹터 비중 파이가 이미 쓴다.
- 대시보드 초기화가 `A1:Z` / 26열 범위이므로 `AA` 이후에 쓰면 다음 실행 때 지워지지 않고
  남는다. `Y:Z` 안에 있어야 한다.
- 배치는 기존 상수(`chartColStart`, `chartColSecondary`, `chartRowSpacing`)를 따른다.

## 에러 처리

키가 없으면 기능만 꺼지고 실행은 계속된다는 기존 원칙을 따른다.

| 상황 | 동작 |
|---|---|
| `STOCK_DATA_OPENAI_API_KEY` 없음 | ETF 카테고리를 못 매김 → 해당 거래는 `미분류`. 경고 로그로 "지수 분류에 OpenAI 키 필요" 안내 |
| `FMP_API_KEY` 없음 | 해외 전량 `미분류`. 국내 지수 비중은 정상 표시 |
| 섹터가 `ETF` 인데 산업이 taxonomy 밖 | `미분류` + 경고 로그. 임의로 "테마" 로 밀어넣지 않는다 |
| 거래 0건 / 섹터 전무 | 섹션 헤더만 쓰고 차트 생략("나라별 섹터 비중" 과 같은 패턴) |
| FMP 일시 오류 | 기존 negative-cache 동작 유지(이번 실행만 빈 값, 다음 실행 재시도) |

## 테스트

- `etfclass`: 이동 후 기존 테스트 유지 + 커버드콜(JEPQ)·레버리지(TQQQ)·팩터(SCHD) 케이스,
  taxonomy 밖 응답의 `기타테마` 정규화.
- `fmpcat`: `IsEtf`/`IsFund` 참이면 `("ETF", 카테고리)`, 일반 종목은 기존 동작 유지,
  캐시 v1→v2 마이그레이션 시 구항목 재조회, 분류기 없을 때 폴백.
- `summary/bucketOf`: 27개 카테고리 전부 + 빈 섹터 + taxonomy 밖 값 + 개별종목 테이블 테스트.
- `summary/aggregateIndexWeight`: 전량 매도 종목의 보유원금 0, 부분 매도, 매도 초과 클램프,
  두 열의 비중 합이 각각 100%.
- `summary` 통합: fake Sheets 서버(`sheets.NewWithEndpoint`)로 섹션 작성 검증
  (기존 `sections_test.go` 패턴).

## 적용 절차 (1회)

캐시 버전이 올라가면 자동 재조회되므로 캐시 파일을 지울 필요는 없다.

1. 머지 후 `make backfill-sectors` — 기존 시트 행의 섹터/산업 갱신.
   - 국내 ETF 89건 KIS 재조회(코드당 3회, 3 calls/s 페이싱 → 약 1~2분)
   - 해외 105건 FMP 재조회, OpenAI ETF 재분류 약 124건
2. `make run` — 대시보드에 새 섹션 반영.

## 범위 밖

- 현재 시세 기반 평가금액(국내 KIS·해외 FMP 시세 조회). 배분 판단에는 원금 기준으로 충분한
  반면 종목 수만큼 API 호출과 레이트리밋 관리가 붙는다.
- 지수 대비 내 수익률 비교(벤치마크 수익률 계산). 별도 작업.
