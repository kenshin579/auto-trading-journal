# 대시보드 계좌별 종목수 표시

작성일: 2026-07-25

## 목적

대시보드에서 계좌별로 **보유 종목수**와 **거래 종목수(누적)** 를 한눈에 확인한다.
현재 대시보드에는 계좌 축 정보가 "계좌별 투자비중" 하나뿐이라, 각 계좌가 몇 개
종목으로 구성되어 있는지 알 수 없다.

## 범위

`internal/summary` 의 투자 지표 섹션(`writeInvestmentMetrics`)에 블록 하나를 추가한다.
새 섹션 신설이나 기존 섹션 재배치는 하지 않는다.

## 출력 형태

투자 지표 섹션 안, 기존 `계좌별 투자비중` 블록 **바로 다음**(통화별 투자비중 앞)에
다음 블록을 넣는다.

```
계좌별 종목수            보유    전체
  미래에셋증권_국내계좌    12      30
  미래에셋증권_해외계좌     5      11
  한국투자증권_국내계좌     8      15
  합계                    25      56
```

- 블록 제목 행의 B/C열에 `보유` / `전체` 를 헤더처럼 넣는다
  (나라별 섹터 차트 헬퍼의 헤더 처리와 같은 방식).
- 계좌 정렬은 기존 `계좌별 투자비중` 과 동일하게 `sortedKeys` 사전식 →
  두 블록의 계좌 순서가 일치한다.
- 계좌 라벨은 기존 블록과 동일하게 두 칸 들여쓰기(`"  " + account`).

## 집계 규칙

**종목 식별 키**: `(StockCode, StockName, Currency)`
국내는 종목코드가 채워지고 해외는 티커/이름이 들어오므로, 코드가 비어 있어도
이름으로 구분되도록 셋을 함께 쓴다. `aggregateStock` 의 키에서 계좌만 뺀 형태와 같다.

**거래종목수(전체)**: 해당 계좌에서 매수·매도 어느 쪽이든 한 번이라도 등장한 고유 종목 수.

**보유종목수**: 계좌 내에서 `Σ매수수량 − Σ매도수량 > 1e-9` 인 종목 수.
(부동소수 오차 방지를 위해 0 이 아닌 1e-9 와 비교)

**합계 행**: 계좌별 값의 **단순 합**. 같은 종목을 두 계좌에서 매수했다면 2 로 센다.
표의 세로 합과 합계 행이 어긋나지 않는 쪽을 택한다.

**빈 입력**: 거래가 하나도 없어 계좌가 없으면 블록 자체(제목 행 포함)를 생략한다.

## 코드 변경점

1. `internal/summary/insights.go` — 순수 집계 함수 추가
   ```go
   type accountStockCount struct {
       account    string
       held, total int
   }
   func aggregateAccountStockCount(trades []model.Trade) []accountStockCount
   ```
   계좌 사전식 정렬 결과를 반환한다. 합계 행은 호출부에서 더한다.

2. `internal/summary/insights.go` — `writeInvestmentMetrics` 안에서 블록 행 생성.
   이 블록의 행만 `[]any{label, held, total}` 3열이고 나머지 행은 기존대로 2열이다
   (Sheets 는 ragged row 를 허용한다).

3. `internal/summary/insights.go` — 데이터 쓰기 범위를
   `%s!A%d:B%d` → **`%s!A%d:C%d`** 로 변경.

4. 서식: 종목수는 퍼센트도 원화도 아니므로 `pctRows` / `krwRows` 에 넣지 않는다.
   `collectMetricsFormats` 는 수정하지 않는다.

## 영향 검토

- 대시보드는 매 실행 `A1:Z` 를 클리어 후 재작성하므로 C열 잔여값 문제가 없다.
- 다른 섹션은 A:H(월별)·A:K(종목별)를 쓰지만 행이 겹치지 않는다.
  파이 차트 데이터는 N:O 라 무관하다.
- 투자 지표 섹션이 계좌 수 + 1(제목) + 1(합계) 만큼 길어지지만, 이후 섹션 시작행은
  `currentRow` 반환값 기반이라 자동으로 밀린다. 별도 조정이 필요 없다.
